# Initial Competency Questions

Competency questions are used to test whether the ontology can answer the questions the framework is intended to support.

## Activities and competencies

1. Which competencies are required to perform a particular engineering activity?
2. Which competencies are required to review or validate that activity's output?
3. Can implementation and review competencies be represented separately?
4. Which activities has an engineer performed repeatedly with observable evidence?

## Artifacts and evidence

5. What artifacts are produced by an implementation activity?
6. What artifacts are evaluated by the corresponding review activity?
7. What evidence was produced during review?
8. Which evidence items support a competency assessment?
9. Which recurring findings may indicate a competency gap?

## AI assistance and human validation

10. Which engineering activities were assisted by an AI system?
11. Which AI system assisted each activity?
12. What artifacts were produced or modified during AI-assisted work?
13. Which human-validation activity was performed?
14. Which acceptance criteria were applied during human validation?
15. What observable evidence supports the decision to accept, reject, or revise the AI-assisted output?

## Measurement and quality

16. Which measurements apply to an activity or artifact?
17. Which quality or acceptance criteria apply?
18. Can review findings be traced to quality criteria?
19. Can repeated measurements support targeted coaching without treating a single metric as a complete measure of competency?

## Coaching

20. Which evidence triggered a coaching recommendation?
21. Which competency does a coaching intervention target?
22. What evidence should be collected after coaching to determine whether observable performance changed?
23. Can the framework distinguish coaching for implementation skills from coaching for review/validation skills?

## Reuse

24. Can the activity → artifact → competency → evidence → assessment → coaching pattern be reused across requirements, design, coding, and testing?
25. Which concepts should align to an existing software-engineering ontology instead of being redefined locally?

## Evaluation criteria

A future ontology review should test whether these questions can be expressed as SPARQL queries or answered through an application built on the RDF graph.

Failure to answer a competency question is a signal to revise the model; it is not evidence that the associated engineering practice is ineffective.
